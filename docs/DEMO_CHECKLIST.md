# WOLI 시연 체크리스트

3-5분 발표 기준의 안정적인 데모 순서입니다.

## 1. 시작 전

- [ ] 테스트 연락처를 중요 연락처에 저장한다.
- [ ] 설정 > 집중 알림 기준에서 `균형` 모드를 선택한다.
- [ ] 답장 시연까지 필요하면 허용 앱 또는 `시연` 모드를 준비한다.
- [ ] 테스트 메시지 앱에서 알림이 뜨도록 준비한다.
- [ ] 앱 설정 > 알림 / TTS 검증에서 알림 접근과 TTS 상태를 확인한다.
- [ ] 앱 설정 > 하드웨어 검증에서 ESP32 또는 시뮬레이션 연결을 확인한다.
- [ ] 서보 잠금/해제 각도가 안전한지 확인한다.
- [ ] 실기기 시연이면 [ESP32 BLE 실기기 검증](ESP32_BLE_HARDWARE_TEST.md)의 배선과 STATUS 동기화를 먼저 확인한다.

## 2. 발표 흐름

1. 홈에서 오늘의 집중 목표를 보여준다.
2. 집중 시간을 25분 또는 50분으로 설정한다.
3. 월이 기기를 연결하거나 시뮬레이션으로 연결한다.
4. 중요 연락처를 보여주고, 집중 중 허용할 연락만 남긴다는 점을 설명한다.
5. 설정 > 집중 알림 기준에서 일반 메신저는 제외되고 중요 연락처/긴급/허용 앱만 안내된다고 설명한다.
6. 집중 알림 전달 화면에서 알림 접근, 포그라운드 알림, 전화 권한 상태를 확인한다.
7. 하드웨어 검증 화면에서 `STATUS`와 mount/lock/hand/battery/session 상태를 보여준다.
8. 스마트폰 거치 입력을 바꿔 `mount=1` Notify가 반영되는 것을 보여준다.
9. 짧은 시연 세션을 시작해 `START` 뒤 `lock=1`, `session=1`과 집중 눈 화면을 보여준다.
10. 테스트 알림 또는 전화 이벤트를 발생시켜 TTS 안내와 답장/전화 제어 흐름을 보여준다.
11. 손 접근 입력을 한 번 감지해 경고 화면과 손 접근 횟수 +1을 보여주고, 감지를 유지해도 횟수가 더 늘지 않는 것을 보여준다.
12. 손 접근을 해제해 `hand=0` Notify 뒤 기본 집중 눈 화면으로 자동 복귀하는 것을 보여준다.
13. 정상 완료 시 `SESSION_END` 뒤 `lock=0`, `session=0`, 집중 완료 화면과 세션 리포트를 보여준다. 중도 종료는 기존 미션 흐름으로만 설명한다.

## 3. 실패 대비

- ESP32 연결 실패: 설정 > 하드웨어 검증에서 `WOLI-Simulator`로 연결한다.
- 메시지 답장 실패: 설정 > 알림 / TTS 검증에서 앱별 성공/실패 이력을 보여준다.
- 일반 메신저가 안내되지 않음: 설정 > 집중 알림 기준에서 허용 앱 또는 `시연` 모드를 켠다.
- 전화 제어 실패: Android 정책상 일부 기기에서 best-effort라고 설명하고 수신 감지/TTS 안내를 중심으로 시연한다.
- 알림 미수신: 알림 접근 설정과 앱 알림 설정을 다시 열어 확인한다.
- TTS 출력 실패: 기기 볼륨과 미디어 출력 장치를 확인하고, 화면 이벤트 흐름으로 대체한다.
- BLE 연결 해제: `WOLI-DT01`을 다시 검색해 연결한 뒤 하드웨어 검증의 `STATUS`로 실제 상태를 다시 동기화한다. 시뮬레이션은 실기기 BLE/센서 검증의 대체 증거가 아니다.

## 4. 심사위원에게 강조할 포인트

- 집중을 방해하는 스마트폰 자체를 물리적으로 멀리 두는 로봇형 UX
- 모든 연락을 차단하지 않고 중요한 연락만 선별하는 현실적인 디지털 디톡스
- 일반 카톡/문자를 기본 제외해 집중 목적을 해치지 않는 알림 정책
- 알림, 전화, BLE, 서보, 센서 상태가 하나의 집중 세션으로 연결되는 점
- Android 정책 차이를 앱별 검증 대시보드와 시뮬레이션 경로로 투명하게 다루는 점
