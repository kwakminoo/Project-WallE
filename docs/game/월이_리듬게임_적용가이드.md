# 월이 · 집중 모드 중도 해제 리듬게임 — 적용 가이드

## 무엇을 / 왜

기획안 **4.5 중도 해제 방지 미션**의 "행동 마찰 장치"를 정통 리듬게임으로 구현했습니다.
흐름은 그대로입니다: 집중 시간을 못 채운 채 종료를 시도 → `QuitConfirmScreen`("정말 종료할까요?") →
"미션 시작" → **리듬게임** → 통과해야만 물리 잠금이 풀립니다.

기존 화면은 "정해진 순서대로 레인 탭하기"라 리듬게임이 아니었습니다. 이번에 **노트가 레인을 따라
떨어지고 판정선에서 타이밍에 맞춰 탭 → Perfect/Good/Miss 판정**하는 방식으로 교체했고, 난이도는
기획 의도(충동적 해제를 한 번 더 생각하게 만드는 정도)에 맞춰 **적당한 마찰(약 20~30초, 집중해야 통과)**로 잡았습니다.

## 변경 요약 (4개 파일)

| 파일 | 상태 | 내용 |
|---|---|---|
| `focus/WoliRhythmGame.kt` | 신규 | 순수 Kotlin 게임 엔진 — 차트 생성·판정·점수·통과 규칙. 단위 테스트 대상. |
| `ui/screens/RhythmMissionScreen.kt` | 신규 | 새 Compose 화면 — 프레임 루프(withFrameNanos)·노트 렌더·레인 입력·결과 오버레이. |
| `ui/screens/FocusScreens.kt` | 수정 | 구버전 `RhythmMissionScreen` + `RhythmShellVisual` 제거(중복 선언 방지). |
| `test/.../WoliRhythmGameTest.kt` | 신규 | 엔진 단위 테스트 12개. |

> **MainActivity / 네비게이션은 손댈 필요 없습니다.** 새 화면의 시그니처가 기존과 동일
> (`RhythmMissionScreen(onSuccess, onCancel)`)하고, 같은 패키지(`com.woli.app.ui.screens`)에 있어
> `MainActivity`의 import와 `Routes.RHYTHM_MISSION` 연결이 그대로 유지됩니다.

## 적용 방법 (셋 중 하나)

### A. git 패치 — 팀 협업에 추천
```bash
cd Project-WallE
git apply --stat  rhythm-game.patch   # 무엇이 바뀌는지 미리보기
git apply --check rhythm-game.patch   # 충돌 여부 확인
git apply         rhythm-game.patch   # 적용
```
`--check`에서 충돌이 나면(= 로컬 `FocusScreens.kt`가 GitHub `main`과 다르면) 아래 B 또는 C를 쓰세요.

### B. zip 덮어쓰기 — 로컬이 `main`과 동기화된 경우
```bash
unzip -o walle-rhythm-game-files.zip -d Project-WallE
```
zip 안의 4개 파일이 저장소의 제자리에 들어갑니다.

### C. 수동 — 로컬이 많이 달라졌을 때 가장 안전
1. 신규 파일 3개를 그대로 추가: `WoliRhythmGame.kt`, `RhythmMissionScreen.kt`, `WoliRhythmGameTest.kt`.
2. `FocusScreens.kt`에서 **아래 두 함수만 통째로 삭제**:
   - `@Composable fun RhythmMissionScreen(onSuccess: () -> Unit, onCancel: () -> Unit) { ... }`
   - `@Composable private fun RhythmShellVisual(targetLane: Int) { ... }`

   두 함수를 안 지우면 같은 이름이 중복 선언되어 컴파일 에러가 납니다. (`MainActivity`는 그대로 두세요.)

## 동작 흐름 / 통합 지점

- **진입**: `QuitConfirmScreen`의 "미션 시작" → `Routes.RHYTHM_MISSION` → `RhythmMissionScreen`.
- **성공**(목표 성공 수 도달) 시 기존과 동일하게 호출:
  `recordMissionAttempt(success = true)` → `WoliFocusSessionController.complete(MissionUnlocked)` →
  `WoliDeviceCenter.setLocked(false)` → `WoliFocusGuardService.stop(context)` → `onSuccess()`(홈으로).
- **실패**(허용 실패치 초과 또는 노트 소진 후 목표 미달) 시:
  `recordMissionAttempt(success = false)` 후 "다시 시도 / 집중 계속하기" 오버레이 표시.
- 세션 리포트의 **미션 성공/시도 카운트**에 그대로 집계됩니다(`missionSuccessCount / missionAttemptCount`).

## 난이도 조절 (한 줄이면 끝)

`RhythmMissionScreen.kt` 상단:
```kotlin
val config = remember { WoliRhythmConfig.Moderate }   // Light / Moderate / Intense
```
또는 직접 값을 지정:
```kotlin
val config = remember {
    WoliRhythmConfig(
        laneCount = 3,        // 레인 수 (Intense는 4)
        bpm = 95,             // 템포
        totalNotes = 28,      // 총 노트 수
        approachMs = 1500,    // 노트가 떨어지는 시간 (작을수록 빠르고 어려움)
        perfectWindowMs = 80, // Perfect 판정 폭 (ms)
        goodWindowMs = 150,   // Good 판정 폭 (ms)
        requiredHits = 18,    // 통과에 필요한 성공(Perfect+Good) 수
        maxMisfires = 10,     // 놓침+헛침 허용치 (넘으면 실패 → 재시도)
    )
}
```
프리셋 요약 — **Light**(몇 초, 심리적 장벽만) · **Moderate**(기본, 20~30초) · **Intense**(4레인·빠름, 발표 임팩트용).

> 확장 아이디어: 집중 시간(`session.config.durationMinutes`)이 길수록 더 어려운 프리셋을 고르면,
> "오래 집중했을수록 깨기 아깝게" 만드는 심리 설계를 넣을 수 있습니다.
